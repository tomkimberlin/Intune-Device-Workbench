# Graph response handling — 2026.11.04

This review started from `e03d54d54640cb15104dd1640828f8fc40be26fa`. Its [Windows baseline run](https://github.com/tomkimberlin/Intune-Device-Workbench/actions/runs/41859447768) passed 331 offline checks, 20 native clipboard checks, and synthetic preview rendering.

## Reproduced failures and fixes

- `Invoke-MgGraphRequest` HTTP exceptions expose `Response.StatusCode`. The app read only `ResponseStatusCode`, losing 401, 403, 404, 429, and 503 statuses before UI completion. A shared extractor now preserves both shapes and standard `HttpRequestException.StatusCode`. The existing UI can require sign-in after a 401, revoke recovery verification, clear displayed secrets, and distinguish permission failures, throttling, and outages.
- The inventory worker accepted missing or malformed `value` collections as successful empty data. It also allowed a next-page link to switch to another Graph collection or an individual record. Refresh now rejects malformed collections, records without usable IDs, malformed links, and links outside the original collection. The existing error path preserves the last complete device list. Valid empty pages still follow their complete next-link URL unchanged.

The same 30 response cases produced 28 failures on the unmodified app and zero failures with the fix. The tests execute the actual operation bodies in fresh PowerShell runspaces, matching the production worker's scope. This matters: the main test suite's strict mode can reject a missing property that the production worker would otherwise silently accept.

The [Windows validation run](https://github.com/tomkimberlin/Intune-Device-Workbench/actions/runs/41860519767) for `2970f3fc66f92ecdaec20a340dee69b6cf5dc077` passed **371 offline checks, 20 native clipboard checks, and synthetic preview rendering**. The 40 added checks cover 30 response scenarios, seven status-extraction cases, and three WPF workflow assertions. The 37 tests that do not need WPF also passed with an isolated PowerShell 7.6.9 runtime on macOS.

## Coverage

`Tests/Test-GraphResponses.ps1` exercises malformed collections and links, valid JSON inventory joining, an opaque pagination token, late collection failure, and the SDK's HTTP exception shape across inventory, LAPS, and BitLocker operations. `Tests/Test-Workflow.ps1` also runs the actual inventory operation through asynchronous worker completion and unshown WPF controls to check the operator-visible consequences.

The review checked delegated account/tenant/scope validation, metadata-only inventory, per-selection recovery reads, response identity checks, verification expiry and cancellation, clipboard cleanup, and portal-link validation. No additional changes were justified in those paths. Device writes such as sync, restart, wipe, and retire remain unimplemented. The batch POST contains only GET subrequests. Permissions, verification settings, and tenant configuration were not changed.

## Remaining release checks

Automated Windows tests use synthetic data and a disposable CI runner. They do not establish live tenant recovery, Windows Hello/PIN/biometrics, physical display scaling, screen-reader behavior, or actual session lock/disconnect behavior on an operator's laptop. Follow [WINDOWS-SMOKE-TEST.md](WINDOWS-SMOKE-TEST.md) for those checks; live privileged recovery requires the operator's participation and separate approval. This review does not change the project's early-release status.
